# Toward a public release

The current baseline is Alltabs 0.1.0 for personal testing. Store publication follows polishing and validation; it is not yet scheduled.

## Polish

- [ ] Use Alltabs daily on Windows and macOS; record concrete friction and bugs.
- [ ] Refine spacing, readability, icon clarity, and interactions based on actual use.
- [ ] Check keyboard navigation, focus visibility, screen-reader labels, and light/dark contrast.
- [ ] Review long titles, long device names, narrow panels, and large tab collections.

## Validate

- [ ] Compare real synced tabs against Chrome History for PC, Mac, Android, and iPhone.
- [ ] Confirm repeated opening, background opening, copying links, and bulk actions.
- [ ] Check saved state across panel closing, browser restart, extension reload, and multiple browser windows.
- [ ] Check stale/offline devices, empty sync data, renamed devices, and hidden-device restoration.
- [ ] Run model, browser-interface, and real-extension checks against the release candidate.
- [ ] Review permissions, privacy claims, and packaged files.

## Prepare publication

- [ ] Choose the final name and store description after checking availability.
- [ ] Prepare screenshots and required store artwork from the polished release.
- [ ] Publish a privacy-policy page and establish a support/contact channel.
- [ ] Complete Chrome Web Store permission and privacy disclosures.
- [ ] Update version and release notes; build and verify the distribution ZIP.
- [ ] Tag the tested release in Git.
- [ ] Submit for store review when ready.

Remote tab closing and direct OneTab integration remain deferred. Revisit them only as separate feature decisions.
